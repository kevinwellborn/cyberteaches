Domain 1.0: General Security Concepts vocabulary

  • CIA triad: Confidentiality, integrity, and availability: the three goals of security. 1.1 Security Concepts and Controls →
  • Non-repudiation: Proof that a specific person took an action, so they cannot deny it later. 1.1 Security Concepts and Controls →
  • Defense in depth: Layering many controls so that when one fails, another still stops the attacker. 1.1 Security Concepts and Controls →
  • Zero trust: A model where no user or device is trusted by default, and every request is verified. 1.1 Security Concepts and Controls →
  • Compensating control: An alternative used when the normal control cannot be put in place. 1.1 Security Concepts and Controls →
  • Detective control: Finds an incident while or after it happens, such as an IDS alert or a log review. 1.1 Security Concepts and Controls →
  • Change advisory board (CAB): The group that reviews and approves proposed changes. 1.2 Change Management and Security →
  • Backout plan: Steps to undo a change and return to the last working state if it fails. 1.2 Change Management and Security →
  • Maintenance window: A scheduled time for changes when the impact on users is lowest. 1.2 Change Management and Security →
  • Impact analysis: Studying what a change could affect before approving it. 1.2 Change Management and Security →
  • Symmetric encryption: Encryption that uses the same key to encrypt and decrypt. 1.3 Cryptography and PKI →
  • Asymmetric encryption: Encryption that uses a public key and a matching private key. 1.3 Cryptography and PKI →
  • Certificate authority (CA): A trusted organization that issues and signs digital certificates. 1.3 Cryptography and PKI →
  • Salt: A random value added to a password before hashing so identical passwords get different hashes. 1.3 Cryptography and PKI →
  • Digital signature: A hash signed with a private key that proves who sent data and that it was not changed. 1.3 Cryptography and PKI →
  • Hardware security module (HSM): A dedicated device that stores and uses cryptographic keys securely. 1.3 Cryptography and PKI →

Domain 2.0: Threats, Vulnerabilities, and Attacks vocabulary

  • Threat: Anything that could exploit a vulnerability and cause harm. 2.1 Threat and Vulnerability Characteristics →
  • Threat intelligence: Information about threats and attackers, organized so a team can act on it. 2.1 Threat and Vulnerability Characteristics →
  • ISAC: Information Sharing and Analysis Center: a group where organizations in one sector share threat information. 2.1 Threat and Vulnerability Characteristics →
  • CVSS: Common Vulnerability Scoring System: a 0 to 10 score of how severe a vulnerability is. 2.1 Threat and Vulnerability Characteristics →
  • Nation-state actor: An attacker working for a government, with large resources and long-term goals. 2.2 Threat Actors and Motivations →
  • Advanced persistent threat (APT): A skilled attacker who stays hidden inside a network for a long time. 2.2 Threat Actors and Motivations →
  • Hacktivist: An attacker motivated by a political or social cause. 2.2 Threat Actors and Motivations →
  • Shadow IT: Technology used inside an organization without the IT department's approval. 2.2 Threat Actors and Motivations →
  • Threat vector: The path or method an attacker uses to get into a system. 2.3 Threat Vectors and Sources →
  • Quishing: Phishing that uses a QR code to send victims to a malicious site. 2.3 Threat Vectors and Sources →
  • Business email compromise (BEC): An attack that uses a hijacked or spoofed business email account to trick staff into sending money or data. 2.3 Threat Vectors and Sources →
  • Watering hole attack: Infecting a website that the target group is known to visit. 2.3 Threat Vectors and Sources →
  • Attack surface: All the points where an attacker could try to get into a system. 2.4 Vulnerabilities and Attack Surfaces →
  • Zero-day: A vulnerability that is exploited before the vendor has released a fix. 2.4 Vulnerabilities and Attack Surfaces →
  • Race condition: A flaw where the result depends on the timing of events, such as TOCTOU. 2.4 Vulnerabilities and Attack Surfaces →
  • VM escape: Breaking out of a virtual machine to reach the host or other virtual machines. 2.4 Vulnerabilities and Attack Surfaces →
  • Fileless malware: Malware that runs in memory with legitimate system tools instead of a file on disk. 2.5 Indicators of Malicious Activity →
  • Password spraying: Trying a few common passwords against many accounts to avoid lockouts. 2.5 Indicators of Malicious Activity →
  • SQL injection: Putting database commands into an input field so the database runs them. 2.5 Indicators of Malicious Activity →
  • Impossible travel: Logins from places too far apart to reach in the time between them, a sign of a stolen account. 2.5 Indicators of Malicious Activity →
  • Prompt injection: Hiding instructions in input so an AI model ignores its intended rules. 2.6 AI Threats and Vulnerabilities →
  • Data poisoning: Corrupting a model's training data so it learns incorrect or harmful behavior. 2.6 AI Threats and Vulnerabilities →
  • Jailbreaking (AI): Tricking an AI model into ignoring its safety rules. 2.6 AI Threats and Vulnerabilities →
  • Hallucination: An AI output that sounds confident but is false or made up. 2.6 AI Threats and Vulnerabilities →
  • Deepfake: AI-generated audio, image, or video that convincingly imitates a real person. 2.6 AI Threats and Vulnerabilities →
  • Explainability: How well people can understand why an AI model produced a result. 2.6 AI Threats and Vulnerabilities →

Domain 3.0: Security Architecture vocabulary

  • Shared responsibility model: How security duties are split between a cloud provider and its customer. 3.1 Architecture Models →
  • Infrastructure as code (IaC): Building and configuring systems from code templates instead of by hand. 3.1 Architecture Models →
  • Air-gapped: Physically separated from other networks, including the internet. 3.1 Architecture Models →
  • Operational technology (OT): Systems that monitor and control physical equipment, such as industrial control systems. 3.1 Architecture Models →
  • Screened subnet: A network zone between the internet and the internal network for public-facing servers, also called a DMZ. 3.2 Infrastructure Security Architecture →
  • Fail closed: When a security device fails, it blocks traffic instead of letting it through. 3.2 Infrastructure Security Architecture →
  • IPS: An intrusion prevention system that sits inline and blocks detected attacks. 3.2 Infrastructure Security Architecture →
  • Jump server: A hardened server that admins connect to first before reaching sensitive systems. 3.2 Infrastructure Security Architecture →
  • Data at rest: Data stored on a drive, database, or backup. 3.3 Data Protection →
  • Data in transit: Data moving across a network. 3.3 Data Protection →
  • Data sovereignty: The rule that data is subject to the laws of the country where it is stored. 3.3 Data Protection →
  • Data loss prevention (DLP): Tools that detect and block sensitive data from leaving the organization. 3.3 Data Protection →
  • Hot site: A fully equipped backup location that can take over almost immediately. 3.4 Resilience and Recovery →
  • Load balancing: Spreading work across several servers so none is overloaded and one can fail safely. 3.4 Resilience and Recovery →
  • UPS: An uninterruptible power supply: a battery that keeps equipment running during short outages. 3.4 Resilience and Recovery →
  • Tabletop exercise: A discussion-based walk-through of how a team would respond to a scenario. 3.4 Resilience and Recovery →

Domain 4.0: Security Operations vocabulary

  • Hardening: Reducing a system's attack surface by removing or disabling what it does not need. 4.1 Mitigating Controls and Hardening →
  • Secure baseline: A standard, approved configuration that systems are built and checked against. 4.1 Mitigating Controls and Hardening →
  • Application allow list: A list of approved programs; anything not on it is blocked. 4.1 Mitigating Controls and Hardening →
  • Least privilege: Giving users and systems only the access they need to do their job. 4.1 Mitigating Controls and Hardening →
  • Asset inventory: An up-to-date list of the organization's hardware, software, and data. 4.2 Asset Management →
  • Sanitization: Removing data from media so it cannot be recovered, such as by overwriting. 4.2 Asset Management →
  • Degaussing: Using a strong magnet to erase data on magnetic media. 4.2 Asset Management →
  • Certificate of destruction: A document from a vendor proving that media was destroyed. 4.2 Asset Management →
  • CVE: Common Vulnerabilities and Exposures: a public ID number for a known vulnerability. 4.3 Vulnerability Management →
  • False positive: A scan result that reports a vulnerability that is not really there. 4.3 Vulnerability Management →
  • Bug bounty: A program that pays outside researchers for responsibly reporting vulnerabilities. 4.3 Vulnerability Management →
  • SIEM: A system that collects and correlates logs from many sources and raises security alerts. 4.4 Monitoring and Alerting →
  • Alert tuning: Adjusting rules so alerts catch real problems without too many false positives. 4.4 Monitoring and Alerting →
  • NetFlow: Network data that records which systems communicated, when, and how much. 4.4 Monitoring and Alerting →
  • SCAP: Security Content Automation Protocol: standards for automatically checking system configurations. 4.4 Monitoring and Alerting →
  • Multifactor authentication (MFA): Logging in with two or more different kinds of factors, such as a password and a phone. 4.5 Identity and Access Management →
  • Single sign-on (SSO): One login that gives access to many applications. 4.5 Identity and Access Management →
  • Privilege creep: A user slowly collecting more access than their current job needs. 4.5 Identity and Access Management →
  • Privileged access management (PAM): Tools that tightly control and monitor admin accounts, such as just-in-time access. 4.5 Identity and Access Management →
  • SOAR: Security orchestration, automation and response: tools that connect security systems and automate responses. 4.6 Automation, Orchestration, and Defensive AI →
  • Playbook: A step-by-step response plan, often automated, for a type of incident. 4.6 Automation, Orchestration, and Defensive AI →
  • Agentic AI: AI that can plan and take actions on its own to reach a goal. 4.6 Automation, Orchestration, and Defensive AI →
  • Behavioral baseline: A record of normal activity used to spot unusual behavior. 4.6 Automation, Orchestration, and Defensive AI →
  • Containment: Limiting an incident so it cannot spread, for example by isolating an infected host. 4.7 Incident Response →
  • Eradication: Removing the cause of an incident, such as malware or a compromised account. 4.7 Incident Response →
  • Lessons learned: The final review after an incident that improves future response. 4.7 Incident Response →
  • Threat hunting: Actively searching for hidden attackers instead of waiting for an alert. 4.7 Incident Response →
  • Chain of custody: A record of everyone who handled evidence, proving it was not tampered with. 4.8 Investigations and Digital Forensics →
  • Order of volatility: Collecting the evidence that disappears fastest, such as memory, first. 4.8 Investigations and Digital Forensics →
  • Legal hold: An instruction to preserve data that may be needed for legal action. 4.8 Investigations and Digital Forensics →
  • Packet capture: A recording of network traffic that can be analyzed later. 4.8 Investigations and Digital Forensics →

Domain 5.0: Security Program Management and Oversight vocabulary

  • Acceptable use policy (AUP): Rules for how employees may use the organization's systems and network. 5.1 Security Governance →
  • Standard: A specific, required rule or setting that supports a policy. 5.1 Security Governance →
  • Data owner: The senior person accountable for a set of data and how it is classified. 5.1 Security Governance →
  • Data custodian: The person or team that manages and protects data day to day. 5.1 Security Governance →
  • Annualized loss expectancy (ALE): Expected yearly loss from a risk: SLE multiplied by ARO. 5.2 Risk Management →
  • Risk register: A list of identified risks with their owners, ratings, and responses. 5.2 Risk Management →
  • Risk transference: Shifting the cost of a risk to someone else, such as an insurer. 5.2 Risk Management →
  • Recovery time objective (RTO): The longest a system can be down before the impact is unacceptable. 5.2 Risk Management →
  • Supply chain attack: Compromising a target by attacking a vendor, product, or update it relies on. 5.3 Third-Party Risk and Procurement →
  • Service-level agreement (SLA): A contract that defines the level of service a vendor must provide, such as uptime. 5.3 Third-Party Risk and Procurement →
  • Right-to-audit clause: A contract term that lets a customer audit the vendor's security. 5.3 Third-Party Risk and Procurement →
  • Non-disclosure agreement (NDA): A contract that requires parties to keep shared information confidential. 5.3 Third-Party Risk and Procurement →
  • Compliance: Meeting the requirements of laws, regulations, contracts, and policies. 5.4 Compliance and Privacy →
  • Data subject: The person whom personal data is about. 5.4 Compliance and Privacy →
  • Right to be forgotten: A person's right under laws such as the GDPR to have their personal data deleted. 5.4 Compliance and Privacy →
  • Attestation: A formal statement that controls are in place and working. 5.4 Compliance and Privacy →
  • Penetration test: An authorized, simulated attack to find weaknesses before real attackers do. 5.5 Audits, Assessments, and Penetration Testing →
  • Rules of engagement: The agreed scope, timing, and limits of a penetration test. 5.5 Audits, Assessments, and Penetration Testing →
  • Unknown environment test: A penetration test where the testers start with no inside information. 5.5 Audits, Assessments, and Penetration Testing →
  • MITRE ATT&CK: A public knowledge base of attacker tactics and techniques. 5.5 Audits, Assessments, and Penetration Testing →
  • Security awareness training: Teaching staff to recognize and report threats and follow security practices. 5.6 Security Awareness →
  • Phishing simulation: A safe, fake phishing email sent to staff to measure and improve awareness. 5.6 Security Awareness →
  • Operational security (OPSEC): Protecting small pieces of information that attackers could combine. 5.6 Security Awareness →
  • Reporting culture: An environment where people feel safe reporting mistakes and suspicious activity. 5.6 Security Awareness →
