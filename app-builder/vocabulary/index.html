Module 1: Find a problem worth solving vocabulary

  • Problem: Something that is hard, slow, annoying, or unfair for a group of people. 1.1 Spot problems around you →
  • Pain point: A specific moment when the problem hurts, like forgetting an assignment the night before it is due. 1.1 Spot problems around you →
  • Brainstorm: Writing down many ideas quickly without judging them yet. 1.1 Spot problems around you →
  • Scope: How big your project is. Small scope means fewer features, done well. 1.1 Spot problems around you →
  • Originality: Your own thinking and work, not a copy of an existing app. 1.1 Spot problems around you →
  • User: A person who will use your app. 1.2 Talk to real people →
  • Target audience: The specific group of people your app is made for. 1.2 Talk to real people →
  • Interview: A short conversation where you ask questions and mostly listen. 1.2 Talk to real people →
  • Open question: A question that cannot be answered with yes or no, such as "How do you keep track of homework now?" 1.2 Talk to real people →
  • Feedback: What people tell you about your idea or app that helps you improve it. 1.2 Talk to real people →
  • Purpose: What your app is for. 1.3 Write your one-sentence purpose →
  • Purpose statement: One clear sentence that says who the app helps, what it does, and why. 1.3 Write your one-sentence purpose →
  • Benefit: The good result for the user, such as saving time or feeling less stressed. 1.3 Write your one-sentence purpose →
  • Core feature: The one main thing your app must do to deliver its purpose. 1.3 Write your one-sentence purpose →
  • Pitch: A very short explanation of your idea, said out loud. 1.3 Write your one-sentence purpose →
  • Intellectual property (IP): Creations that belong to someone, such as images, music, characters, code, and brand names. 1.4 Make sure your idea is safe and your own →
  • Open source: Code that its authors let others use, usually with a license that says how. 1.4 Make sure your idea is safe and your own →
  • License: The rules for how you may use someone else's work. 1.4 Make sure your idea is safe and your own →
  • Privacy: People's right to control their personal information. 1.4 Make sure your idea is safe and your own →
  • Disclosure: Telling people clearly what tools, libraries, and AI help you used. 1.4 Make sure your idea is safe and your own →
  • Build journal: A dated log of your work: what you did, what went wrong, and how you fixed it. 1.5 Set up your project and build journal →
  • Project folder: One folder that holds all the files for your app. 1.5 Set up your project and build journal →
  • Version history: Saved earlier copies of your work, so you can go back if something breaks. 1.5 Set up your project and build journal →
  • GitHub: A free website for storing code and its history. 1.5 Set up your project and build journal →
  • Work session: A block of time you set aside to work on your app. 1.5 Set up your project and build journal →

Module 3: Coding basics vocabulary

  • Platform: Where an app runs, such as a web browser, a phone, or a desktop computer. 3.1 Choose your platform and language →
  • Programming language: A set of words and rules for writing instructions a computer can follow. 3.1 Choose your platform and language →
  • Web app: An app that runs in a web browser and is shared with a link. 3.1 Choose your platform and language →
  • JavaScript: The programming language that makes web pages interactive. 3.1 Choose your platform and language →
  • Code: Instructions written in a programming language. 3.1 Choose your platform and language →
  • Run: To have the computer carry out your code. 3.1 Choose your platform and language →
  • HTML: The language that describes what is on a web page. 3.2 Your first web page: HTML and CSS →
  • Tag: A label in angle brackets, like <p> or <button>, that tells the browser what something is. 3.2 Your first web page: HTML and CSS →
  • Element: One thing on the page, made of an opening tag, its content, and a closing tag. 3.2 Your first web page: HTML and CSS →
  • CSS: The language that describes how a page looks. 3.2 Your first web page: HTML and CSS →
  • Property: One thing CSS can change, such as color or font-size. 3.2 Your first web page: HTML and CSS →
  • id: A unique name you give an element so code can find it. 3.2 Your first web page: HTML and CSS →
  • Event: Something that happens in an app, such as a click or a key press. 3.3 Events: make a button do something →
  • Event listener: Code that waits for an event and runs when it happens. 3.3 Events: make a button do something →
  • Click: The event that fires when someone presses a button or taps it. 3.3 Events: make a button do something →
  • getElementById: A JavaScript command that finds the element with a certain id. 3.3 Events: make a button do something →
  • textContent: The words inside an element. Changing it changes what the page shows. 3.3 Events: make a button do something →
  • Input: What the user gives the app, such as a click or typed text. 3.3 Events: make a button do something →
  • Variable: A named place in memory that holds a value. 3.4 Variables: remember things →
  • Value: A piece of data, such as 7, "hello", or true. 3.4 Variables: remember things →
  • Assign: To put a value into a variable, using the equals sign. 3.4 Variables: remember things →
  • String: Text, written inside quotes. 3.4 Variables: remember things →
  • Number: A numeric value you can do math with. 3.4 Variables: remember things →
  • Boolean: A value that is either true or false. 3.4 Variables: remember things →
  • Condition: A question the code asks that is either true or false. 3.5 If / else: make decisions →
  • if statement: Code that runs a block only when a condition is true. 3.5 If / else: make decisions →
  • else: The block that runs when the condition is false. 3.5 If / else: make decisions →
  • else if: A second condition to check when the first one was false. 3.5 If / else: make decisions →
  • Comparison: Checking two values against each other, with ===, !==, <, >, <=, or >=. 3.5 If / else: make decisions →
  • Loop: Code that runs a block again and again. 3.6 Loops: repeat without retyping →
  • for loop: A loop that repeats a set number of times, using a counter. 3.6 Loops: repeat without retyping →
  • while loop: A loop that repeats as long as a condition is true. 3.6 Loops: repeat without retyping →
  • Counter: A variable that keeps track of which round of the loop you are on. It is often named i. 3.6 Loops: repeat without retyping →
  • Iteration: One trip through the loop. 3.6 Loops: repeat without retyping →
  • Infinite loop: A loop that never ends because its condition never becomes false. 3.6 Loops: repeat without retyping →
  • List: An ordered group of values stored under one name. 3.7 Lists: keep many things together →
  • Array: The JavaScript word for a list. 3.7 Lists: keep many things together →
  • Item: One value in a list. Also called an element. 3.7 Lists: keep many things together →
  • Index: The position of an item in a list. In JavaScript the first index is 0. 3.7 Lists: keep many things together →
  • length: How many items are in a list. 3.7 Lists: keep many things together →
  • push: The command that adds an item to the end of a list. 3.7 Lists: keep many things together →
  • Function: A named block of code you can run whenever you need it. 3.8 Functions: name your steps and reuse them →
  • Call: To run a function by writing its name followed by parentheses. 3.8 Functions: name your steps and reuse them →
  • Parameter: A named input a function receives. 3.8 Functions: name your steps and reuse them →
  • Argument: The actual value you pass in when you call a function. 3.8 Functions: name your steps and reuse them →
  • return: The word that sends a result back from a function. 3.8 Functions: name your steps and reuse them →
  • Reuse: Using the same code in more than one place without retyping it. 3.8 Functions: name your steps and reuse them →
  • Hello app: A first small app that proves your tools work and you know the basics. 3.9 Build your hello app →
  • Text box: An <input> element where the user can type. 3.9 Build your hello app →
  • index.html: The usual name for the main file of a web app. 3.9 Build your hello app →
  • Code editor: A program for writing code, with helpful colors and checks. 3.9 Build your hello app →
  • Bug: A mistake in code that makes it behave in a way you did not intend. 3.9 Build your hello app →

Congressional App Challenge track vocabulary

  • Congressional App Challenge (CAC): A yearly app competition for middle and high school students, run district by district by Members of Congress. C.1 What is the Congressional App Challenge? →
  • Congressional district: An area of a state that elects one Member of the U.S. House of Representatives. You compete inside one district. C.1 What is the Congressional App Challenge? →
  • Submission: Everything you turn in: your registration, your demonstration video, and your written answers. C.1 What is the Congressional App Challenge? →
  • Demonstration video: A 1 to 3 minute video that explains your app and shows it working. C.1 What is the Congressional App Challenge? →
  • Judging criteria: What judges score: the quality of the idea, how well it is built and designed, and your coding skill. C.1 What is the Congressional App Challenge? →
  • Eligible: Allowed to enter because you meet every rule. C.2 Check that you can enter →
  • Host district: A congressional district whose Member of Congress is running a challenge this year. C.2 Check that you can enter →
  • Member of Congress: The person elected to represent your district in the U.S. House of Representatives. C.2 Check that you can enter →
  • ZIP+4: A 9-digit ZIP code, such as 90210-1234. Registration asks for it for your home and your school. C.2 Check that you can enter →
  • Deadline: The last moment you can submit. After it passes, your entry cannot be changed in any way. C.2 Check that you can enter →
  • Team: Two to four students who submit one app together. C.3 Solo or team? →
  • Role: The main job a teammate is responsible for. C.3 Solo or team? →
  • Builder: The teammate who writes most of the code. C.3 Solo or team? →
  • Tester: The teammate who tries the app in many ways to find bugs before the judges do. C.3 Solo or team? →
  • Team profile: The team page one teammate creates when registering. That person invites up to three others. C.3 Solo or team? →
  • Cutoff date: The date after which your app must have been created. C.4 Build by the rules: credits and AI disclosure →
  • Original work: Work created by you or your team, not copied. C.4 Build by the rules: credits and AI disclosure →
  • Technical understanding: Being able to explain how your own code works. C.4 Build by the rules: credits and AI disclosure →
  • Disqualification: Being removed from the contest for breaking a rule. C.4 Build by the rules: credits and AI disclosure →
  • Source code: The code you wrote, which judges may ask to see. C.4 Build by the rules: credits and AI disclosure →
  • Functionality: What your app actually does when someone uses it. C.5 Make the official demo video →
  • Public: A video setting that lets anyone watch. Required by the rules. C.5 Make the official demo video →
  • Penalized: Scored lower for breaking a rule. C.5 Make the official demo video →
  • Registration: Signing up on the official site with your details. C.6 Register, write your answers, and submit →
  • Eligibility quiz: A short set of questions on the official site that confirms you are allowed to enter. C.6 Register, write your answers, and submit →
  • Application: The form with your video link and written answers. C.6 Register, write your answers, and submit →
  • Submission period: The dates when entries are accepted. In 2026 it ran from May to late October. C.6 Register, write your answers, and submit →
  • Exit questionnaire: A survey every participant fills out after the deadline. C.6 Register, write your answers, and submit →
  • Embargo: A date before which results cannot be announced. C.6 Register, write your answers, and submit →
