Break the core feature into small steps

A whole app is too big to build in one go. Programmers break big jobs into small steps, build one step, test it, and then move on. This is called decomposition, and it is the most useful habit you can learn. Each step should be small enough to finish in one work session.

Start by writing what should happen in plain words, one line at a time. This is called pseudocode. It is not real code, so there are no syntax errors to fight. You are just thinking clearly about the order of things.

Then build in tiny pieces. Get one line of your plan working, and run it. Never write fifty lines before running anything. When you run after every small change, a new bug can only be in the few lines you just wrote.

Pseudocode for "add an assignment"

When the user clicks Add:
  read the assignment name from the text box
  read the due date
  if the name is empty, show "Type a name first" and stop
  otherwise make a new assignment with that name and date
  add it to the list of assignments
  sort the list by due date
  show the list on the page
  clear the text box

Do this

  1. Write your core feature as pseudocode: five to ten plain lines.
  2. Turn each line into a small task. Order them so each one builds on the last.
  3. Open your index.html from lesson 3.9 and rename things to fit your app, or start a fresh file.
  4. Build the first task only. Run it. Fix it until it works.
  5. Write a journal entry, then move to the next task next session.

With your class: Be the computer

About 15 minutes. Working on your own? Do these steps with a friend or someone at home.

  1. Trade pseudocode with a partner.
  2. Your partner is now the computer. They read your lines one at a time and do exactly what each line says, nothing more.
  3. Any time the computer has to guess, they say "stuck." Mark that line.
  4. Rewrite the marked lines so no guessing is needed. Then switch roles.
  5. Turn your fixed pseudocode into your list of build steps.

Break the core feature into small steps vocabulary

  • Decomposition: Breaking a big problem into smaller ones you can solve one at a time.
  • Pseudocode: A plan for code written in plain words.
  • Algorithm: A set of steps that solves a problem.
  • Incremental development: Building and testing one small piece at a time.
  • Test: To run your code and check that it does what you expect.
  • Working session goal: The one small thing you plan to finish today.
