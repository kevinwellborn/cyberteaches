Lab 4 Teacher Key: Grocery Store Downtime

The complete incident timeline, the CIA analysis with evidence, the traceroute interpretation, a model VLAN plan, and setup notes for an optional class SFTP server.

Optional: set up the class SFTP server (Part 1)

Any Linux machine or virtual machine that you control on the school's lab network works. Never use a production server.

sudo apt install openssh-server        # SSH and SFTP both use port 22
sudo adduser intern                    # give students the password in class
sudo mkdir -p /var/log/invdb
sudo cp invdb01-audit.log /var/log/invdb/
sudo chmod 644 /var/log/invdb/invdb01-audit.log

Students then run sftp intern@<server address>, cd /var/log/invdb, and get invdb01-audit.log. If no server is available, students download the file and write the command sequence with an explanation.

Part 1 answers: pwd shows the current directory; mkdir -p lab4 && cd lab4 makes and enters the folder; inside SFTP, pwd, cd, and ls act on the remote server; get downloads to the local working directory, so the file lands in /home/student/lab4/invdb01-audit.log. SFTP runs over SSH on port 22, so the credentials and the log are encrypted; FTP on port 21 sends both in plain text.

Weak point: the break-room computer (Fa0/16) is shared by employees and customers, was left on overnight, and sits on the same flat network (VLAN 1, 10.0.0.0/24, no internal firewall) as the registers and the inventory server. The customer Wi-Fi (password on the window) is on the same network too.

CIA key (Part 3)

  • Confidentiality: compromised. Unauthorized login as inv_admin from a non-admin PC after hours (23:36); SELECT and EXPORT of the customer_loyalty table (23:38, 23:40); connection to a known malicious IP (23:41); 1.4 GB sent to 203.0.113.99 (08:47).
  • Integrity: compromised. UPDATE prices × 10 on 1,240 rows (08:52:11); stock_qty set to 0 on 310 rows (08:52:14); the attempt to delete audit entries (08:53, denied) shows an effort to hide changes; wrong register prices and false out-of-stock messages.
  • Availability: compromised. Traffic 40 times baseline (09:31); switch uplink drops (09:33); payment timeouts and "Declined - timeout" (09:38–09:40); online orders cancelled; camera video loss; slow office PC.
  • Threat versus performance indicators: threat indicators are the port scan, repeated failed logins, after-hours access, the connection to a known malicious IP, and the large outbound transfer. Performance indicators are the output drops, timeouts, failed connections, and packet loss. Here the performance problems were caused by the attacker's traffic flood, which is why both kinds of entry must be read together.

Traceroute key (Part 4)

Both runs have 5 hops. Before opening, every hop is under 20 ms. During the incident, the delay (about 400 ms, with lost probes) already appears at hop 1, the store's own gateway (10.0.0.1), and continues through every later hop. A problem that starts at hop 1 is inside the store's network, not at the ISP or the processor. That matches the broadcast flood and the switch uplink drops. Accept starting at the network layer (gateway and IP path) or at the data link layer (switch drops, broadcast traffic on the LAN) with that reasoning.

Impact key (Part 5)

  • Short-term: long lines and overcharges on the busiest Saturday of a holiday weekend; cash-only registers; cancelled pickup orders and lost sales; staff time spent on manual price checks; refunds owed. Peak timing multiplies the impact.
  • Long-term: 48,912 loyalty members' data exposed (notification duties under data-protection law, possible fraud); reputational damage and lost customer trust; financial loss; possible payment-card compliance review because the payment gateway shares a flat network with an untrusted PC (PCI DSS).

Verification: show vlan brief lists Fa0/1–6 under VLAN 10, Fa0/7–9 under 20, and so on; ping between registers succeeds; ping from a register to the payment gateway succeeds through the router; ping from the break-room PC or a guest laptop to 10.0.20.x fails after the ACL is applied.

Controls key

  • Scan and lateral movement: segmentation (VLANs) plus deny-by-default rules between VLANs; NGFW or IPS with alerting.
  • Password guessing: account lockout after 3–5 failures; strong, unique passwords; MFA for administrative access.
  • Shared inv_admin account: individual named accounts with least privilege; disable logins outside business hours; change the password now.
  • Exfiltration: block outbound connections to known malicious IPs; monitor and alert on large outbound transfers.
  • Break-room PC: AUP for the shared computer, automatic sign-out, no customer use, and no access to store systems.
  • Customer Wi-Fi: separate guest network with its own SSID, WPA2 or WPA3, a captive portal, and no internal access.

Availability plan

Accept plans that add redundancy (backup cellular internet for the payment gateway, a secondary switch for the registers), a UPS for the network closet and registers, monitoring and alerting on traffic spikes, an IPS to block floods, and documented patching. Restore the price and inventory data from a backup taken before 08:52 Saturday, then verify it against the audit log.
