Lab 2: Computer Lab Disconnected

Six help desk tickets arrive during one class period in Room 204. Your school technology support team restores every station using indicator lights, ping results, and IP configurations, documents the room's network, and then secures and segments it so the problems are less likely to return.

At a glance

Based on Unit Scenario 2A in the AP Networking Course Framework

  • Time: 4 class periods (45 min)
  • Team size: 4 (one role each)
  • Book lessons: 2.1, 2.2, 2.3, 2.5, 2.6 (2.4 for the AI step)
  • Deliverables: network troubleshooting incident report, network documentation, and a security and segmentation plan

Learning objectives

  • 2.1.A Identify likely root causes of a SOHO network issue.
  • 2.1.B Determine an appropriate solution.
  • 2.2.D Document an existing network including devices, addresses, and connections.
  • 2.5.B Determine security controls to mitigate vulnerabilities.
  • 2.6.B Determine device grouping for segmentation.
  • 2.4.A Evaluate an AI-generated suggestion.

Skills: 1.A, 1.C, 2.A–2.C, 3.A–3.D, 4.A–4.D

The situation

You are on the school technology support team. During third period, problems pile up in the computer science classroom: a screen goes black, single stations lose their connection, the teacher's laptop slows to a crawl, and then a whole row goes offline. Restore functionality as quickly as possible and report what happened so it does not happen again.

Starter files

  • Help desk tickets 2041–2046 (.txt)
  • Indicator light observations and device manual key (.txt)
  • ipconfig, ifconfig, and ping output (.txt)
  • Room 204 device inventory (.csv, opens in a spreadsheet)
  • Router administration page capture (.txt)
  • Incident report and documentation template (Word)
  • Packet Tracer build sheet (.txt, for Part 5)

Team roles

Project lead
Keeps the team on the plan and the clock, makes sure every requirement is covered, and makes the final call when the team is split. Owns the team log.
Data analyst
Reads the evidence (readings, logs, command output), compares values with the thresholds from the book, and states what each piece of evidence shows.
Configuration technician
Plans and carries out the configuration or fix in the simulator or on the device, and runs the verification tests.
Documentation lead
Builds the deliverable, keeps diagrams and tables consistent, and records how the team used and checked AI.

Teams of three: the project lead also keeps documentation. Teams of five: add an AI liaison who writes the prompts and leads the evaluation of AI output. Rotate roles from lab to lab so that every student does each job once.

Walkthrough

Part 1: Triage the tickets (Day 1)

  1. Read all six tickets. Decide the order you will work them in and explain why in your team log. (Hint: which ticket affects the most people?)
  2. For each ticket, record the user's description, the affected device, and the diagnostic data from the indicator lights and the command output.
  3. Interpret each piece of evidence using Lesson 2.1: green, orange or red, and unlit lights; ping response times over 100 ms or more than 1–2% packet loss; 169.254.x.x APIPA addresses; and a loopback-only 127.0.0.1 result.

Part 2: Determine causes and solutions (Day 1–2)

  1. For each ticket, write the most likely root cause and the evidence that supports it.
  2. Choose the simplest appropriate solution first (reseat or replace a cable, try a different port, restart a device, ipconfig /release and ipconfig /renew, enable the adapter, switch to wired). Write the exact steps.
  3. Describe how you will verify each fix: the station reaches the internet and the shared drive (10.204.0.10) and pages load without delay. Ask your teacher for the verification results, and record them.

Part 3: Document the network (Day 2)

  1. Using the inventory, draw a network diagram of Room 204 with the router, both switches, the file server, the printer, representative stations, and the wireless devices. Use solid lines for wired and dashed lines for wireless connections.
  2. Label each device with a consistent name and its IP address. Add the MAC addresses for the router, file server, printer, and teacher laptop, and mark which devices use static addresses.
  3. Answer in your report: Why should the printer and file server keep static addresses while the stations use DHCP?

Part 4: Secure and segment the room (Day 3)

  1. Review the router administration page. List every vulnerability you find and its possible impact (Lesson 2.5).
  2. Ask an AI assistant: "Write a security and segmentation plan for a high school computer lab with 16 student stations, a teacher laptop, a file server, a printer, a smart projector, a smart thermostat, and visiting guest speakers' laptops." Paste the reply into your log, and evaluate it: what is realistic, what is overcomplicated or missing, and what is wrong for this room?
  3. Write your team's plan: the corrected router settings, and a segmentation plan that groups devices by risk level and user type (for example, teacher and server, student stations, IoT, and guest). Explain how a firewall between segments limits lateral movement.

Part 5: Build and verify in a simulator (Day 4)

  1. Follow the Packet Tracer build sheet to build Room 204: router, two switches, four stations, the file server, the printer, and a wireless access point.
  2. Configure DHCP on the router for the station range, give the server and printer static addresses, and secure the wireless network with WPA2 and a strong password (Packet Tracer does not offer WPA3 on every device).
  3. Verify: run ipconfig on two stations and ping the file server and gateway. Then recreate one ticket from Part 1 (for example, unplug a cable or turn off a station's adapter) and show the fix.

Deliverables and rubric

Your incident report (use the template) must include: user descriptions of each loss of function and the affected devices; the diagnostic data with explanations; probable causes and the solutions you chose; verification of restored function; and recommendations to avoid similar issues. Attach the network diagram and the security and segmentation plan.
