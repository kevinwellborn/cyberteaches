Unit 1: Introduction to Security vocabulary

  • Phishing: A message that pretends to come from a trusted source to steal information or install malware. 1.1 Understanding Social Engineering →
  • Pretexting: Inventing a believable story (a pretext) to get someone to share information. 1.1 Understanding Social Engineering →
  • Tailgating: Following an authorized person through a secure door without badging in. 1.1 Understanding Social Engineering →
  • Spear phishing: Phishing aimed at one specific person or group, using details about them. 1.1 Understanding Social Engineering →
  • Credential harvesting: Collecting usernames and passwords through a fake login page. 1.2 Suspicious Website Logins →
  • Typosquatting: Registering a domain that is a common misspelling of a real one. 1.2 Suspicious Website Logins →
  • Domain: The name of a site, read right to left from the top-level domain (for example, .com). 1.2 Suspicious Website Logins →
  • HTTPS: An encrypted web connection. It protects data in transit but does not prove a site is legitimate. 1.2 Suspicious Website Logins →
  • Evil twin: A rogue Wi-Fi access point that copies the name of a real one. 1.3 Best Practices for Public Networks →
  • VPN: A virtual private network that encrypts all your traffic to a trusted server. 1.3 Best Practices for Public Networks →
  • Eavesdropping: Secretly capturing data sent over a network. 1.3 Best Practices for Public Networks →
  • Auto-join: A device setting that connects to known network names automatically, which evil twins exploit. 1.3 Best Practices for Public Networks →
  • Deepfake: AI-generated audio, image, or video that imitates a real person. 1.4 AI-Based Cybersecurity Attacks →
  • Voice cloning: Using AI to copy a person's voice from a recording. 1.4 AI-Based Cybersecurity Attacks →
  • Prompt injection: Hiding instructions in content so an AI system does something its owner did not intend. 1.4 AI-Based Cybersecurity Attacks →
  • Automation: Using software to run attacks at large scale with little human effort. 1.4 AI-Based Cybersecurity Attacks →
  • Anomaly detection: Flagging activity that differs from normal patterns. 1.5 Leveraging AI in Cyber Defense →
  • False positive: An alert for something that is actually harmless. 1.5 Leveraging AI in Cyber Defense →
  • False negative: A real attack that the system misses. 1.5 Leveraging AI in Cyber Defense →
  • Human in the loop: Keeping a person responsible for reviewing and approving AI decisions. 1.5 Leveraging AI in Cyber Defense →

Unit 2: Securing Spaces vocabulary

  • CIA triad: Confidentiality, integrity, and availability: the three goals of security. 2.1 Cyber Foundations →
  • Vulnerability: A weakness that could be exploited. 2.1 Cyber Foundations →
  • Threat: Anyone or anything that could exploit a vulnerability. 2.1 Cyber Foundations →
  • Defense in depth: Using several layers of protection. 2.1 Cyber Foundations →
  • Shoulder surfing: Watching someone type a password or PIN. 2.2 Physical Vulnerabilities and Attacks →
  • Dumpster diving: Searching trash for useful information. 2.2 Physical Vulnerabilities and Attacks →
  • Baiting: Leaving infected USB drives where victims will find and plug them in. 2.2 Physical Vulnerabilities and Attacks →
  • Badge cloning: Copying the signal from an access card. 2.2 Physical Vulnerabilities and Attacks →
  • Access control vestibule (mantrap): Two doors where the second opens only after the first closes, stopping tailgating. 2.3 Protecting Physical Spaces →
  • Preventive control: A control that stops an attack from happening. 2.3 Protecting Physical Spaces →
  • Deterrent control: A control that discourages attackers, such as warning signs. 2.3 Protecting Physical Spaces →
  • Least privilege: Giving people only the access they need. 2.3 Protecting Physical Spaces →
  • Detective control: A control that identifies an attack, like a camera or alarm. 2.4 Detecting Physical Attacks →
  • Tamper-evident seal: A seal that shows visible damage if opened. 2.4 Detecting Physical Attacks →
  • Access log: A record of who entered which door and when. 2.4 Detecting Physical Attacks →
  • Alert: A notification sent when a rule detects suspicious activity. 2.4 Detecting Physical Attacks →

Unit 3: Securing Networks vocabulary

  • DoS / DDoS: Overwhelming a system with traffic, from one source or many. 3.1 Network Vulnerabilities and Attacks →
  • On-path attack: An attacker secretly relays and possibly changes traffic between two parties. 3.1 Network Vulnerabilities and Attacks →
  • DNS spoofing: Giving out false DNS answers so a name leads to the attacker's server. 3.1 Network Vulnerabilities and Attacks →
  • Port scan: Probing a device to see which network services are listening. 3.1 Network Vulnerabilities and Attacks →
  • Managerial control: A policy or procedure that guides people's behavior. 3.2 Protecting Networks: Managerial Controls and Wireless Security →
  • Acceptable use policy (AUP): Rules for how people may use an organization's systems. 3.2 Protecting Networks: Managerial Controls and Wireless Security →
  • WPA3: The current Wi-Fi security standard. 3.2 Protecting Networks: Managerial Controls and Wireless Security →
  • Default credentials: Factory-set usernames and passwords that attackers already know. 3.2 Protecting Networks: Managerial Controls and Wireless Security →
  • Segmentation: Dividing a network into separate zones. 3.3 Protecting Networks: Segmentation →
  • VLAN: A virtual LAN that groups devices logically, regardless of physical location. 3.3 Protecting Networks: Segmentation →
  • DMZ: A buffer zone for public-facing servers. 3.3 Protecting Networks: Segmentation →
  • Lateral movement: An attacker moving from one compromised system to others. 3.3 Protecting Networks: Segmentation →
  • Firewall rule: A condition and an action (allow or deny) for matching traffic. 3.4 Protecting Networks: Firewalls →
  • Port: A number that identifies a service, such as 443 for HTTPS or 22 for SSH. 3.4 Protecting Networks: Firewalls →
  • Implicit deny: Blocking any traffic not explicitly allowed. 3.4 Protecting Networks: Firewalls →
  • Stateful firewall: A firewall that tracks connections and allows replies to approved traffic. 3.4 Protecting Networks: Firewalls →
  • IDS: Intrusion detection system: alerts on suspicious traffic. 3.5 Detecting Network Attacks →
  • IPS: Intrusion prevention system: detects and blocks suspicious traffic. 3.5 Detecting Network Attacks →
  • Signature-based detection: Matching traffic against patterns of known attacks. 3.5 Detecting Network Attacks →
  • SIEM: A system that gathers and correlates security logs from many devices. 3.5 Detecting Network Attacks →

Unit 4: Securing Devices vocabulary

  • Malware: Software designed to harm or take control of a system. 4.1 Device Vulnerabilities and Attacks →
  • Ransomware: Malware that encrypts files and demands payment. 4.1 Device Vulnerabilities and Attacks →
  • Worm: Malware that spreads across networks on its own. 4.1 Device Vulnerabilities and Attacks →
  • Zero-day: A vulnerability unknown to the vendor, so no patch exists yet. 4.1 Device Vulnerabilities and Attacks →
  • MFA: Multifactor authentication: using two or more different kinds of factors. 4.2 Authentication →
  • Brute force: Trying every possible password until one works. 4.2 Authentication →
  • Hash: A one-way fingerprint of data used to check passwords without storing them. 4.2 Authentication →
  • Password manager: An app that creates and stores unique strong passwords. 4.2 Authentication →
  • Hardening: Reducing vulnerabilities by changing settings and removing extras. 4.3 Protecting Devices →
  • Patch: An update that fixes a vulnerability. 4.3 Protecting Devices →
  • Full-disk encryption: Encrypting the whole drive so a stolen device's data stays unreadable. 4.3 Protecting Devices →
  • Attack surface: All the points where an attacker could try to get in. 4.3 Protecting Devices →
  • Indicator of compromise (IoC): Evidence that a system may have been breached. 4.4 Detecting Attacks on Devices →
  • EDR: Endpoint detection and response: tools that monitor and respond on devices. 4.4 Detecting Attacks on Devices →
  • Containment: Isolating a system to stop an attack from spreading. 4.4 Detecting Attacks on Devices →
  • Event log: A record of actions on a device, like logins and installs. 4.4 Detecting Attacks on Devices →

Unit 5: Securing Applications and Data vocabulary

  • SQL injection: Inserting database commands into input to read or change data. 5.1 Application and Data Vulnerabilities and Attacks →
  • XSS: Cross-site scripting: injecting script into a web page that runs in other users' browsers. 5.1 Application and Data Vulnerabilities and Attacks →
  • Input validation: Checking that input matches what is expected before using it. 5.1 Application and Data Vulnerabilities and Attacks →
  • Data breach: Unauthorized access to sensitive data. 5.1 Application and Data Vulnerabilities and Attacks →
  • Data classification: Labeling data by how sensitive it is. 5.2 Protecting Applications and Data: Managerial Controls and Access Controls →
  • RBAC: Role-based access control: permissions tied to job roles. 5.2 Protecting Applications and Data: Managerial Controls and Access Controls →
  • Separation of duties: Splitting critical tasks so no one person can complete them alone. 5.2 Protecting Applications and Data: Managerial Controls and Access Controls →
  • Authorization: Deciding what an authenticated user is allowed to do. 5.2 Protecting Applications and Data: Managerial Controls and Access Controls →
  • Plaintext / ciphertext: Readable data before encryption / scrambled data after. 5.3 Protecting Stored Data with Cryptography →
  • Symmetric encryption: One shared secret key for both encrypting and decrypting. 5.3 Protecting Stored Data with Cryptography →
  • AES: Advanced Encryption Standard: the widely used symmetric cipher. 5.3 Protecting Stored Data with Cryptography →
  • Key space: The number of possible keys. Larger is harder to brute force. 5.3 Protecting Stored Data with Cryptography →
  • Public key: A key you share freely so others can encrypt to you or verify your signature. 5.4 Asymmetric Cryptography →
  • Private key: A key only you hold, used to decrypt and sign. 5.4 Asymmetric Cryptography →
  • Digital signature: Proof a message came from the key owner and was not changed. 5.4 Asymmetric Cryptography →
  • Certificate: A file, vouched for by a trusted authority, that links a public key to an identity. 5.4 Asymmetric Cryptography →
  • Parameterized query: A database query that treats user input strictly as data, blocking SQL injection. 5.5 Protecting Applications →
  • Output encoding: Converting special characters so input displays as text instead of running as code. 5.5 Protecting Applications →
  • Patch management: Tracking and applying software updates. 5.5 Protecting Applications →
  • Backup: A copy of data kept separately so it can be restored. 5.5 Protecting Applications →
  • Audit log: A record of who accessed or changed data. 5.6 Detecting Attacks on Data and Applications →
  • File integrity monitoring: Alerting when important files change unexpectedly. 5.6 Detecting Attacks on Data and Applications →
  • Data exfiltration: Unauthorized copying of data out of an organization. 5.6 Detecting Attacks on Data and Applications →
  • Baseline: A picture of normal activity used to spot differences. 5.6 Detecting Attacks on Data and Applications →
