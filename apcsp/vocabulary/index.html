Big Idea 1: Creative Development vocabulary

  • Computing innovation: A new or improved program, device, or idea that uses computing as a key part of how it works. 1.1 Collaboration →
  • Pair programming: Two programmers sharing one task: a driver writes the code and a navigator reviews it and plans ahead. 1.1 Collaboration →
  • Diverse perspectives: Ideas from people with different backgrounds and experiences, which help a team avoid bias and blind spots. 1.1 Collaboration →
  • Feedback: Comments from users or teammates used to improve a program. 1.1 Collaboration →
  • Program: A collection of instructions that a computer follows to do a task. 1.2 Program Function and Purpose →
  • Input: Data sent to a program, from a user, a device, or another program. 1.2 Program Function and Purpose →
  • Output: Data a program sends out, such as text on a screen, a sound, or a file. 1.2 Program Function and Purpose →
  • Event: An action, like a key press or mouse click, that triggers code to run. 1.2 Program Function and Purpose →
  • Iterative development: Repeating the design, build, and test steps to refine a program over many cycles. 1.3 Program Design and Development →
  • Incremental development: Building a program in small pieces, testing each piece before adding more. 1.3 Program Design and Development →
  • Documentation: Written descriptions of how a program or piece of code works and how to use it. 1.3 Program Design and Development →
  • Comment: A note in the code for people to read; the computer ignores it. 1.3 Program Design and Development →
  • Syntax error: A mistake in the rules of the language, such as a missing bracket, that stops the program from running. 1.4 Identifying and Correcting Errors →
  • Logic error: A mistake in the algorithm that makes the program behave incorrectly or give a wrong answer. 1.4 Identifying and Correcting Errors →
  • Run-time error: An error that happens while the program is running, often stopping it unexpectedly. 1.4 Identifying and Correcting Errors →
  • Edge case: An input at the extreme end of what is allowed, such as 0, an empty list, or the largest value. 1.4 Identifying and Correcting Errors →

Big Idea 2: Data vocabulary

  • Bit: A binary digit, 0 or 1; the smallest unit of data in a computer. 2.1 Binary Numbers →
  • Byte: A group of 8 bits, which can represent 256 different values. 2.1 Binary Numbers →
  • Binary: A base-2 number system that uses only the digits 0 and 1. 2.1 Binary Numbers →
  • Abstraction: Hiding details to focus on what matters, such as treating a group of bits as a letter or color. 2.1 Binary Numbers →
  • Data compression: Reducing the number of bits used to represent data. 2.2 Data Compression →
  • Lossless: Compression that allows the original data to be restored exactly. 2.2 Data Compression →
  • Lossy: Compression that permanently removes some data to save more space. 2.2 Data Compression →
  • Run-length encoding: A lossless method that replaces repeated values with a count, such as AAAA becoming 4A. 2.2 Data Compression →
  • Information: The patterns and meaning people get from analyzing data. 2.3 Extracting Information from Data →
  • Metadata: Data that describes other data, such as a file's size, author, or creation date. 2.3 Extracting Information from Data →
  • Data cleaning: Fixing or removing incorrect, missing, or inconsistent data before analysis. 2.3 Extracting Information from Data →
  • Correlation: A relationship where two values tend to change together; it does not prove cause. 2.3 Extracting Information from Data →
  • Filter: Keeping only the data that meets a condition, such as students in grade 10. 2.4 Using Programs with Data →
  • Data visualization: A chart, graph, or map that shows data so patterns are easier to see. 2.4 Using Programs with Data →
  • Scalability: How well a solution keeps working as the amount of data grows. 2.4 Using Programs with Data →
  • Data set: A collection of related data, often organized in rows and columns. 2.4 Using Programs with Data →

Big Idea 3: Algorithms and Programming vocabulary

  • Variable: A named storage location for a value that can change while the program runs. 3.1 Variables and Assignments →
  • Assignment: Storing a value in a variable, written with ← in AP pseudocode. 3.1 Variables and Assignments →
  • Data type: The kind of value stored, such as a number, a string, or a Boolean. 3.1 Variables and Assignments →
  • Boolean: A value that is either true or false. 3.1 Variables and Assignments →
  • List: An ordered collection of elements stored under one name. 3.2 Data Abstraction →
  • Element: One value inside a list. 3.2 Data Abstraction →
  • Index: The position number of an element; AP pseudocode starts at 1. 3.2 Data Abstraction →
  • Data abstraction: Giving a collection of data one name so it can be used without knowing every detail. 3.2 Data Abstraction →
  • Algorithm: A finite set of instructions that completes a task. 3.3 Mathematical Expressions →
  • Sequencing: Running steps one after another in a set order. 3.3 Mathematical Expressions →
  • Expression: A combination of values, variables, and operators that produces a single value. 3.3 Mathematical Expressions →
  • MOD: An operator that gives the remainder after division, for example 17 MOD 5 = 2. 3.3 Mathematical Expressions →
  • String: An ordered sequence of characters, such as "hello". 3.4 Strings →
  • Concatenation: Joining two or more strings end to end. 3.4 Strings →
  • Substring: A part of a string, taken from inside a larger string. 3.4 Strings →
  • Length: The number of characters in a string. 3.4 Strings →
  • Boolean expression: An expression that evaluates to true or false. 3.5 Boolean Expressions →
  • Relational operator: An operator that compares two values, such as > or ≠. 3.5 Boolean Expressions →
  • AND: True only if both conditions are true. 3.5 Boolean Expressions →
  • OR: True if at least one condition is true. 3.5 Boolean Expressions →
  • Selection: Choosing which part of an algorithm to run based on a condition. 3.6 Conditionals →
  • Conditional statement: An IF or IF-ELSE statement that runs code only when a condition is met. 3.6 Conditionals →
  • Condition: A Boolean expression that decides which path the program takes. 3.6 Conditionals →
  • Block: A group of statements that run together, shown inside braces or a box. 3.6 Conditionals →
  • Nested conditional: A conditional statement placed inside another conditional. 3.7 Nested Conditionals →
  • Branch: One possible path through a conditional. 3.7 Nested Conditionals →
  • Trace: Following code step by step by hand to see what it does. 3.7 Nested Conditionals →
  • Iteration: Repeating part of an algorithm a set number of times or until a condition is met. 3.8 Iteration →
  • REPEAT n TIMES: An AP pseudocode loop that runs its block exactly n times. 3.8 Iteration →
  • REPEAT UNTIL: An AP pseudocode loop that stops once its condition becomes true. 3.8 Iteration →
  • Infinite loop: A loop whose ending condition is never met, so it never stops. 3.8 Iteration →
  • Existing algorithm: A known, tested algorithm, such as finding the minimum of a list, that can be reused. 3.9 Developing Algorithms →
  • Efficiency: How much time or memory an algorithm uses as its input grows. 3.9 Developing Algorithms →
  • Equivalent: Producing the same output for every possible input. 3.9 Developing Algorithms →
  • Traversal: Visiting each element of a list, usually with a loop. 3.10 Lists →
  • APPEND: Adds a value to the end of a list. 3.10 Lists →
  • FOR EACH: An AP pseudocode loop that runs once for every element in a list. 3.10 Lists →
  • Linear search: Checking elements one at a time from the start until the target is found. 3.11 Binary Search →
  • Binary search: Repeatedly checking the middle of a sorted list and discarding half. 3.11 Binary Search →
  • Sorted: Arranged in order, such as smallest to largest. 3.11 Binary Search →
  • Procedure: A named group of instructions that may take parameters and return a value; also called a function. 3.12 Calling Procedures →
  • Procedure call: An instruction that runs a procedure. 3.12 Calling Procedures →
  • Argument: A value passed into a procedure when it is called. 3.12 Calling Procedures →
  • Return value: The value a procedure sends back to the code that called it. 3.12 Calling Procedures →
  • Procedural abstraction: Naming a process so it can be used by knowing what it does, not how. 3.13 Developing Procedures →
  • Parameter: A variable in a procedure definition that receives an argument. 3.13 Developing Procedures →
  • Modularity: Dividing a program into separate parts that each do one job. 3.13 Developing Procedures →
  • RETURN: Ends a procedure and sends a value back to the caller. 3.13 Developing Procedures →
  • Library: A collection of prewritten procedures that can be used in new programs. 3.14 Libraries →
  • API: Application program interface: the specification for how to use a library's procedures. 3.14 Libraries →
  • Reuse: Using existing tested code instead of writing it again. 3.14 Libraries →
  • RANDOM(a, b): Returns a random integer from a to b, inclusive. 3.15 Random Values →
  • Inclusive: Includes the end values; RANDOM(1, 6) can return 1 or 6. 3.15 Random Values →
  • Probability: How likely an outcome is, from 0 (never) to 1 (always). 3.15 Random Values →
  • Nondeterministic: Able to give different outputs from the same input on different runs. 3.15 Random Values →
  • Simulation: A program that imitates a real-world process to study or predict it. 3.16 Simulations →
  • Model: A simplified representation of something real. 3.16 Simulations →
  • Assumption: A simplification or guess built into a model that affects its results. 3.16 Simulations →
  • Bias: A tilt in results caused by what a model includes or leaves out. 3.16 Simulations →
  • Reasonable time: Running time that grows at a polynomial rate or slower. 3.17 Algorithmic Efficiency →
  • Unreasonable time: Running time that grows exponentially or faster. 3.17 Algorithmic Efficiency →
  • Heuristic: A shortcut that gives a good-enough solution when the best one takes too long. 3.17 Algorithmic Efficiency →
  • Decision problem: A problem with a yes-or-no answer. 3.18 Undecidable Problems →
  • Decidable: Solvable by an algorithm that gives a correct answer for every input. 3.18 Undecidable Problems →
  • Undecidable: Impossible for any algorithm to answer correctly for all inputs. 3.18 Undecidable Problems →
  • Halting problem: Deciding whether any program will stop running; proven undecidable. 3.18 Undecidable Problems →

Big Idea 4: Computer Systems and Networks vocabulary

  • Packet: A small chunk of data sent across a network with addressing information. 4.1 The Internet →
  • Protocol: An agreed set of rules for how data is sent and received. 4.1 The Internet →
  • IP address: A unique number that identifies a device on the internet. 4.1 The Internet →
  • Bandwidth: The maximum amount of data that can be sent in a fixed amount of time. 4.1 The Internet →
  • Fault tolerance: The ability of a system to keep working when some parts fail. 4.2 Fault Tolerance →
  • Redundancy: Extra parts or paths that can take over when others fail. 4.2 Fault Tolerance →
  • Route: The path packets take from sender to receiver. 4.2 Fault Tolerance →
  • Router: A device that forwards packets toward their destination. 4.2 Fault Tolerance →
  • Sequential computing: Running operations one at a time, in order. 4.3 Parallel and Distributed Computing →
  • Parallel computing: Breaking a task into parts that run at the same time on multiple processors. 4.3 Parallel and Distributed Computing →
  • Distributed computing: Using many networked computers to work on one problem. 4.3 Parallel and Distributed Computing →
  • Speedup: Sequential running time divided by parallel running time. 4.3 Parallel and Distributed Computing →

Big Idea 5: Impact of Computing vocabulary

  • Beneficial effect: A positive result of a computing innovation. 5.1 Beneficial and Harmful Effects →
  • Harmful effect: A negative result, which may affect people the creators never considered. 5.1 Beneficial and Harmful Effects →
  • Unintended consequence: An effect the creators did not plan or predict. 5.1 Beneficial and Harmful Effects →
  • Impact: The effect an innovation has on society, the economy, or culture. 5.1 Beneficial and Harmful Effects →
  • Digital divide: Unequal access to computing devices, the internet, and the skills to use them. 5.2 Digital Divide →
  • Access: Being able to use technology when needed. 5.2 Digital Divide →
  • Broadband: High-speed internet service. 5.2 Digital Divide →
  • Equity: Fairness in who gets resources and opportunities. 5.2 Digital Divide →
  • Training data: Data used to teach a machine learning system how to make decisions. 5.3 Computing Bias →
  • Machine learning: A way for computers to find patterns in data and improve without being explicitly programmed. 5.3 Computing Bias →
  • Representative data: Data that fairly reflects all the groups a system will be used on. 5.3 Computing Bias →
  • Crowdsourcing: Getting input, work, or funding from a large group of people online. 5.4 Crowdsourcing →
  • Citizen science: Scientific research done with help from members of the public. 5.4 Crowdsourcing →
  • Crowdfunding: Raising money for a project from many people, each giving a small amount. 5.4 Crowdsourcing →
  • Open access: Making research or data free for anyone to use. 5.4 Crowdsourcing →
  • Intellectual property: Creations of the mind, such as code, music, writing, and images. 5.5 Legal and Ethical Concerns →
  • Copyright: A legal right that protects a creator's work from being copied without permission. 5.5 Legal and Ethical Concerns →
  • Creative Commons: A set of licenses that let creators share work under conditions they choose. 5.5 Legal and Ethical Concerns →
  • Open source: Software whose code is freely available for anyone to view, use, and change. 5.5 Legal and Ethical Concerns →
  • PII: Personally identifiable information: data that can identify a specific person. 5.6 Safe Computing →
  • Multifactor authentication: Signing in with two or more kinds of proof, such as a password and a code from your phone. 5.6 Safe Computing →
  • Encryption: Scrambling data so only someone with the right key can read it. 5.6 Safe Computing →
  • Phishing: A trick, usually an email or text, that tries to get you to reveal private information. 5.6 Safe Computing →
